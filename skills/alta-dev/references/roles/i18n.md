# Internationalisation et localisation

**If a human reads it, it is translatable.** A user-facing literal in the code is a defect, even in a
product that ships one language today: it is the moment the second language becomes a rewrite instead
of a file. Read with `ui-ux.md`, which owns the wording itself.

## Les clés, pas les phrases

- Every user-facing string comes from a catalogue, addressed by a **stable, namespaced key**
  (`role.card.limits`, `error.target.offline`). The key never changes when the wording does.
- The source language is one translation among others, not a privileged default hardcoded in the code.
- **Adding a language is adding a file**, never editing code. That is P8 applied to content: if a new
  locale requires touching a conditional, the design is wrong.
- Keys are grouped by feature, like the code, so a feature can be deleted with its translations.

## Ce qui casse une traduction

- **Never concatenate translated fragments.** Word order, agreement and gender differ between
  languages, so a sentence assembled from three keys is untranslatable. One key per full sentence,
  with placeholders inside it.
- **Named placeholders**, never positional, so a translator can reorder them freely.
- **Pluralization goes through the framework's plural rules**, never through `if (n == 1)`. Languages
  have between one and six plural forms; two is a guess that happens to work in English.
- Gender, formality and inflection are the catalogue's business, not the code's.
- Provide **context to the translator**: a comment saying where the string appears, what the variable
  contains, and how much room there is. Without it, one word with three meanings gets one translation.

## Formatage

Dates, times, numbers, currencies, units, lists and sorting are **locale-sensitive**, and none of them
are formatted by hand.

- Format through the locale-aware API, always. A hand-rolled date pattern is a bug in every locale but
  yours.
- Sorting and comparison use the locale's collation, not a byte comparison. Accented characters do not
  sort where their code points are.
- Units and conventions follow the audience, not the developer.

## Mise en page

- Translated text **expands**, often by a third or more, and some languages produce very long
  compounds. A layout tuned to the source language will truncate.
- Never reserve space by counting characters in the source language. Test with the longest locale you
  ship, and with a pseudo-locale that inflates every string.
- If a surface has a hard character or pixel budget, that budget is part of the key's context, and the
  translation is checked against it.
- Right-to-left, when in scope, is a layout mirror and not a text reversal: use logical start and end
  properties rather than left and right.

## Choisir la locale

Declare the resolution order explicitly, and follow it everywhere: the user's explicit preference,
then their account or profile, then the request or device preference, then the product default. Never
the server's own locale, which is an accident of where it runs.

## Fallback et manques

- A declared fallback chain, so a missing key degrades to a sibling locale rather than to a blank.
- A missing key is **loud in development** (visible marker) and **safe in production** (the fallback),
  and it is reported so it gets translated rather than discovered by a user.
- Never ship a machine-translated string as final into a surface the audience trusts, without a review
  pass by someone who speaks it.

## Tests

- Assert on **keys and parameters**, not on translated text, or every wording change breaks the suite
  for no reason.
- A pseudo-locale run catches the two things review misses: strings still hardcoded in the code, and
  layouts that break when text expands.
- The catalogue is linted: no missing key in a shipped locale, no orphan key with no user, no
  duplicate meaning under two keys.

## Ce qui reste en anglais

Identifiers, log messages, code comments, commit messages and internal documentation. The audience for
those is the team, and mixing languages there costs more than it buys. The user-facing content follows
the audience.
